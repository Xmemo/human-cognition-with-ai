# 发布政策

## 公开层与私有分析层

定期研究流程可能会生成比公开 GitHub 版本更丰富的私有 / 面向用户报告。公开文件会经过有意过滤。

### 公开 GitHub 版本包括

- 当前领域判断 / 周度综合；
- 筛选后的论文、预印本、机构报告、研究计划、研讨会与有实质内容的长篇研究分析；
- 来源、发布日期、资料类型，以及适用时的研究设计；
- 主要发现 / 结论；
- 证据等级与方法学限制；
- 中性的“为什么重要”分析；
- 3×3 雷达标签与领域信号摘要；
- 满足纳入标准时的 Iyad Rahwan / Center for Humans and Machines 动态；
- 证据收敛与反证部分；
- 已核验的参考文献与标准来源链接。

### 公开 GitHub 版本排除

- `专家说`；
- `元认知重构`；
- 面向个人的中文文章系列建议；
- 私有图书项目策略；
- 对用户个人项目或私有目标的直接引用；
- 不属于公共研究记录的对话式辅导内容。

类似 `why this matters to you` 这样的个性化句子，在公开版中必须改写成中性的 **为什么重要**。

## 双语政策

1. 研究只执行一次。
2. 翻译 / 编辑适配前先冻结证据集。
3. 中文是主要编辑版本。
4. 英文基于同一证据集做符合英语表达习惯的编辑重写，而不是逐句直译，也不是第二次独立研究。
5. 论文标题、作者、日期、DOI、证据等级、关键限制、条目顺序与来源身份必须保持一致。
6. 已有成熟英文术语的领域概念，应使用该领域的标准术语，而不是从中文机械回译。
7. 网站核心页面必须同时存在中文与英文版本；不得用默认语言 fallback（回退）伪装成已经完成翻译。
8. 中文正文以中文为主。必要英文术语首次出现时采用“中文（English term）”，之后优先只使用中文；论文原题、作者名、DOI 与标准缩写除外。

## 引用政策

- 公开正文优先使用 DOI、出版社、会议、官方机构或 arXiv 链接。
- 通过 Consensus 发现的论文，在使用前必须 fetch / 核验记录，并把 Consensus 记录链接保存在 `references/consensus.md` 或对应日期台账中。
- 不能把搜索结果摘要当成原始论文引用。
- 当原论文 / 报告可用时，不应使用二手新闻替代其关键结论来源。
- 引用次数只是文献计量背景，不是证据等级。

## 历史完整性

Weekly 文件是带日期的研究快照。不能只是为了让语言更漂亮、或让旧周报符合后来形成的新理论，就重写历史研究简报。发现事实或书目信息错误时可以纠正，但修订应在版本历史中保持可追踪。

## 翻译机制

GitHub 本身不会自动翻译 Markdown。项目因此把定期研究流程同时作为编辑翻译层：先冻结同一套证据，再生成中文与英文版本，并统一检查术语、证据等级和来源身份。

网站构建会对核心双语页面执行 parity（对齐）检查。如果规定的核心中文或英文页面缺失，构建应该失败，而不是由 Starlight 自动显示另一语言正文。

未来可以引入 GitHub Actions 自动翻译，但前提是它继续遵守“冻结证据集”规则，并有明确的术语和质量检查层。它不是当前研究检索机制的一部分。
