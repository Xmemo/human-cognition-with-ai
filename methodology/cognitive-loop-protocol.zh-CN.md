# Cognitive Loop Protocol｜认知循环干预与评估协议 v0.1

**状态：方法建议 / 待研究验证｜2026-10-09**  
[English](cognitive-loop-protocol.md) · [认知生态专题](../research/cognitive-ecology.zh-CN.md) · [研究缺口](open-questions-research-gaps.zh-CN.md)

## 0｜目标、非目标与基本原则

**目标**：评估不同的人机交互组织方式，能否改善真实的认知结果，而不是仅让用户感觉“思考得更多”。

**非目标**：提高会话轮数、强制苏格拉底问答、禁止 AI 代劳、把散步当作万能工具、用自评的“洞见指数”代替行为证据。

**第一性原理**：把具体任务拆为所需认知操作，识别人应保留的判断节点、可外化的资源、可观测的反馈，再问每个干预是否产生净收益。

- 对机械性工作优先减少摩擦；不强迫做认知训练。
- 对学习／理解任务，必须评估 AI 离场后的能力。
- 对真实知识工作，还必须评估人在工具辅助下的系统能力、故障韧性、时间成本。
- 身体、环境、真实人际互动是**可调用资源**，不是所有人的统一流程。
- 明确区分外部工具依赖、判断控制权和技能退化。

## 1｜研究对象与任务分类

实验前为每个任务填写：
1. **任务类型**：机械执行 / 学习迁移 / 创造探索 / 决策判断 / 行为改变。
2. **评价标准**：是否有外部正确答案？是否可以由盲评判定质量？是否存在长期结果？
3. **关键认知节点**：问题定义、初步假设、搜索、外部操作、解释、反证、验证、最终取舍、停止。
4. **允许资源**：无工具、纸笔、图形操作、AI、真实人类反馈、身体活动。
5. **潜在伤害与隐私**：避免引导用户在安全攸关的场景依赖未经验证的建议；对语音、健康和社交资料优先最小化收集。

## 2｜三种对照交互

| 条件 | 用户路径 | 假设 |
|---|---|---|
| A. Answer-first | 给问题→AI 可直接生成完整答案→用户审核 | 最低交互成本，可能提高即时产出 |
| B. Human-led scaffold | 用户先表述自己的看法→AI 给针对性反例／证据→用户评估与修订 | 可能改善校准、作者性和迁移 |
| C. Cognitive ecology loop | B 的核心环节 + **自愿**选择在纸笔、图形、散步或真实访谈中进行一次外部行动→返回比较与修订 | 外部操作／情境反馈可能在特定任务上带来增量 |

**重要识别问题**：C 比 B 多了活动时间与注意力。若要检验“散步特异性”或“真实人际反馈特异性”，必须另外设置**等时长控制组**，且把活动组件拆分而不是把整包效果都归因于其中一步。

单次循环建议：
- **Capture**：先记录原始观点／假设（可选跳过）。
- **Externalize**：把信息放到卡片、纸张或可编辑图上，让关系可见。
- **Challenge**：AI 提供可核查的反例、未知之处，而不是代替最后判断。
- **World contact（可选）**：走路、观察、测量、访谈；记下真正新增的外部信息。
- **Evaluate / Revise**：记录证据、观点变化及未解决的问题。
- **Stop / Return**：设退出条件；需要时回到下一轮，避免无穷反思。

在 UI 中，若用户只想完成一项工作，始终允许一键走 Answer-first。

## 3｜最小数据结构

可选事件名和字段如下（不要求记录私密内容全文）：

| 事件 | 建议字段 |
|---|---|
| task_started | task_id（随机）、task_type、condition、timestamp |
| initial_model | claim_present、confidence_0_100、human_authored、optional_text_opt_in |
| tool_action | actor（human/AI/shared）、action_kind（search/edit/move/speech/walk/interview/check）、duration_sec |
| evidence_check | independently_verified、contradicting_evidence_found、source_kind |
| revision | claim_changed、reason_code（evidence/reinterpretation/social-feedback/other）、confidence_0_100 |
| exit | stopped_by（human/AI/limit）、duration_sec、subjective_effort |
| assessment | immediate_score、delayed_no_AI_score、transfer_score、error_detection、recovery_score、rater_blinded |

默认不应上传原始语音、位置信息、生理指标或第三方访谈内容。用户明确同意才存可识别资料；支持删除与导出。事件定义不等于已验证量表。

## 4｜多维评价：至少不混淆六个指标

| 指标 | 可观测代理 | 解释边界 |
|---|---|---|
| **Control** | 谁提出目标、最后判断、拒绝 AI；置信度与准确度是否校准 | 自称“我很自主”不等于有控制权 |
| **Internal Retention** | 24–72 小时后无 AI 的解释、重建、错误修复与近迁移 | 短测验不能证明多年技能变化 |
| **Extended Capability** | 人+AI 与人单独、AI 单独的任务表现差 | 组合好于人不一定好于 AI |
| **System Resilience** | 插入 AI 错误／工具不可用时识错、恢复时间、降级方案 | 避免在真实高风险任务植入错误 |
| **Variance** | 作品／理由／解法的多样性；盲评新颖性；预先指定测度 | 多样性更高不自动意味着质量更好 |
| **Effort / Agency** | 任务耗时、主观负担、所有权、真实行动完成率 | 更多用时与更多点击不是认知收益 |

报告中要明确主要终点（primary outcome）、次要终点、量表是否验证、评价人员是否对实验条件盲法，以及所使用 AI 模型和版本。

## 5｜最低可行的研究试点

**第一轮（可行性，不宣称疗效）**：
- 目标：验证用户能否理解三种交互、顺利完成任务与后测；
- 范围：一个具体领域（例如产品创意推演），任务难度先行试测，避免任务过于简单；
- 设计：随机分配 A/B/C，预先确定主终点（例如延迟无 AI 推理质量）与最小有意义效应；
- 记录：完成率、耗时、AI 参与节点、是否主动跳过、反馈的可用性；
- 后测：延迟 24–72 小时的无 AI 测试 + 在不同题材上的迁移测试；
- 分析：报告每组分布、效应量、置信区间和负结果；不根据主观满意度事后改主终点。

初始小样本只能测试流程可行性，不能据此判定产品提升认知能力。若涉及学习效果、真实用户资料或发表研究，应按适用伦理要求进行审查。

**第二轮（机制拆解）**：把初始独立表述、AI 反问、可拖拽图形、散步、真实交流分别作为组件操纵；比较等时长控制条件，并预先指定相互作用效应和多重比较策略。

## 6｜转化成产品的上线门槛

- **Gate 0｜问题明确**：哪些用户、何种具体任务确实会因现有“答案优先”流程受损？是否有观察或访谈证据？
- **Gate 1｜体验成立**：用户能完成循环，也能自由跳过，不靠强制完成率制造正向数据。
- **Gate 2｜认知价值**：至少一个事前选定的行为型结果优于合适对照，且增益大于额外时间／成本。
- **Gate 3｜商业价值**：用户是否愿意为可重复的认知改善付费，还是只是偶尔觉得有启发？
- **Gate 4｜持续跟进**：真实世界使用和延迟测验重复验证，无效则降级或停止。

商业化指标与认知有效性应分开：留存、付费转化率无法证明用户思维能力提高。

## 7｜与现有系统的关系

- **Human Cognition with AI**：负责文献、证据等级、研究缺口与公开研究框架；
- **Research Lab（未来）**：需要人工批准后才运行研究，不自动把项目假设写回证据基线；
- **Soul Agent**：适合验证现实行动、社会反馈与修订之间的关系；
- **Kapi**：只适合探索可自愿选择的状态调节／休息与后续任务体验，不能把身体信号解释为客观判断正确性；
- **知识库**：记录原始主张、证据、修订和不确定性，而非只保留 AI 最终文本。

## 8｜需要优先证伪的命题

1. 与直接答案相比，额外循环是否只是增加了时间？
2. 当任务需要快速执行或人已经是专家时，脚手架是否反而妨碍表现？
3. 真实世界反馈能否产生**超出纯 AI 反问**的增量效果？
4. AI 辅助的延展能力提高时，内部能力是否可能保持不变甚至下降？其净价值如何判断？
5. 即时新奇感消退后，行为收益是否仍存在？
6. 当许多用户使用类似反思提示时，群体解法的差异是否被进一步压缩？

结论：**设计好的认知循环，应当能被跳过、被反驳、被测量，也能在没有净增益时被撤销。**
